- **🔄 « UNE NOUVELLE VERSION EST EN LIGNE » (v0.737 ; trois signalements de suite)** — ce projet déploie plusieurs fois par jour, et **un onglet resté ouvert fait tourner l'ANCIEN code indéfiniment**. Le service worker ne cache rien (choix délibéré), donc un simple rechargement suffit toujours — encore faut-il **savoir** qu'il faut recharger. Faute de ce signal, un correctif livré a été signalé comme « toujours cassé » **trois fois d'affilée** : à chaque fois le code poussé était juste, la base de données saine, et seul le build chargé était périmé.
  - **Aucune étape de build à maintenir** : l'empreinte est le **nom haché du chunk d'ENTRÉE** (`assets/index-<hash>.js`), que Vite régénère à chaque déploiement, lu dans le HTML servi. Rien à générer, rien qui puisse se désynchroniser. ⚠️ `fetch(..., { cache: 'no-store' })` est indispensable : sans lui on relirait la copie du navigateur et on ne verrait jamais le nouveau déploiement — le bug qu'on cherche à éviter.
  - ⚠️ **On PROPOSE, on ne recharge JAMAIS d'autorité** : l'utilisateur peut être en pleine séance, et un rechargement sauvage lui ferait perdre son écran. Vérification **au retour au premier plan** (`visibilitychange`), pas en boucle. Distinct du garde anti-chunk-périmé du routeur, qui ne se déclenche QU'APRÈS un import raté.
